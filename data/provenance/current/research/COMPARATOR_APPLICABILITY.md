# Common-classifier stopping controls and acquisition-method applicability

Prepared 2 October 2026. This is a design/code applicability audit; it reports no new experiment, timing, fit or test access. The comparison concerns partial **processing** of resident raw signals for a frozen full-input classifier. It does not establish superiority over all active feature acquisition (AFA) systems.

## The common object and two executable reference controls

For each seed retain exactly the frozen classifier, fit-only feature center/scale, any development-selected temperature, genuine feature operators, feature block order, four-block batch endpoints, numeric guards, and candidate-leaf backend used by the certified method. Let `L,U` be the outward-guarded reachable complete-model logits and `l,u` the induced probability bounds. The common partial output is `p = choose_probability(l,u,0)[0]`; the final fallback uses the same exact compiled predictor. Do not use the complete reference output, hidden features or case label to select an online action.

1. **Class-preserving reference rule.** Stop when a class `w` satisfies `L[w] > max(U[c] : c != w)` and the returned minimax probability has `argmax(p) == w`. This proves the returned class equals the complete frozen model's unique winning class, conditional on valid reachable bounds. It does not impose or prove a half-Brier loss tolerance. The probability-box relaxation can contain unrealizable vectors, so retain the explicit output-argmax agreement check rather than assuming the logit proof automatically applies to a different probability construction. Ties and invalid bounds continue. The logit separation prerequisite is cheap: construct minimax `p` only after separation, then stop if it agrees; otherwise continue. Score collapse or the final prefix uses exact fallback. The current kernel returns an unused Brier bound together with `p`; ignore it for this rule, and count all actual work still executed. A specialized probability-only routine may omit the final unused bound arithmetic, but must produce the same `p` and be documented.

2. **Fixed-prefix minimax reference rule.** Select one genuine prefix endpoint on development data, reveal exactly that prefix for every case, then construct its reachable bounds and common minimax `p` once. There is no online estimated benefit and no half-Brier certificate threshold. A requested intermediate prefix is rounded upward to the shared batch endpoint. The all-block candidate is included. Fixed-prefix computation may defer leaf-mask updates and interval/minimax calculation until its stopping checkpoint; repeatedly running an unnecessary certificate would penalize this cheap control. Its complete time includes actual prefix processing, mask/interval work, probability calculation, and dispatch.

`research/control_design.py` implements the reference checks without model/data loading or fitting:

```python
checkpoint_ends(total_blocks, batch_size=4)
canonical_prefix(prefix_blocks, ends)
validate_block_order(order, total_blocks)
certified_class(score_lower, score_upper)  # -1 means not established
decide_stop(rule, processed_blocks, total_blocks, *, probability=None,
            score_lower=None, score_upper=None, prefix_blocks=None,
            confidence_threshold=None, entropy_threshold=None, collapsed=False)
select_development_setting(summaries, *, tolerance, risk_key,
                           time_key='mean_complete_ms', expected_setting_ids=None)
```

`StopDecision` contains `stop`, `reason`, `needs_exact`, `certified_class`, and optional diagnostic. `class_preserving` with separated logits but no `p` returns `minimax_probability_required`, allowing the caller to defer expensive construction. This module is a pure NumPy/Python rule reference, not a benchmark driver. Compile equivalent checks into the same production backend as the main method; charging Python checks to controls and compiled checks to the main method is unfair. The existing Hydraulic and HAR pipelines expose order/endpoints and leaf masks, so a callback/subclass can reuse them without retraining.

## Confidence and entropy development selection

Use the same minimax partial probability, not a separately trained cheap classifier. Confidence stops at `max(p) >= tau`; entropy stops at `H(p)/log(C) <= eta` with `0 log 0 = 0`. Both construct current intervals/minimax probabilities at each shared checkpoint and charge those costs. They make no pointwise loss or class guarantee. A small fixed sweep is provided in `control_design.py`: confidence {0.50, 0.60, 0.70, 0.80, 0.90, 0.95, 0.975, 0.99, 0.995, 1}; normalized entropy {0.01, 0.025, 0.05, 0.10, 0.15, 0.20, 0.30, 0.40, 0.50, 0.70, 1}. Every rule also falls back at the final prefix.

Before the sweep choose and record one primary development constraint: e.g. mean observed-label half-Brier excess relative to the same complete model, or the maximum subject-mean excess on HAR. These are distinct targets; do not choose whichever is more favorable after seeing results. For each locked tolerance, choose the lowest **mean complete online time** among all prespecified settings satisfying that chosen empirical development constraint, with risk then setting ID as deterministic tie breaks. Use identical full development cohorts and timer boundaries; keep all candidate outcomes. Include the exact complete-reference candidate, whose excess is zero. If no non-full candidate passes, select the full reference. Freeze chosen rules before external test access. Development selection is supervised empirical tuning, not a statistical generalization guarantee or a pointwise certificate. Report external constraint violations, empirical every-label excess, predicted-class agreement, tail time and full fallback rate for every selected control.

## Timing and comparison invariants

- Same resident raw cases, full feature definitions and units, fit-only transform, frozen full classifier, precision, temperature, block order, batch endpoints, single-thread settings, warmup, randomized method order and repeated measurement. Hydraulic has 28 blocks/238 coordinates; HAR has 18 blocks/153 coordinates. Use the actual model's group schema.
- Same timers start before actual feature processing and end after final probability/decision. Include routing, bound updates, minimax construction and fallback. Exclude only training, JIT warmup and raw-file I/O at the explicitly stated resident-input boundary. Cache only fitted model structures and training resources, never unprocessed current-case features or complete-case predictions.
- Repeat complete timing separately from trace/profiling. Native and compiled full-input references are both retained. Verify probabilities and bounds against native full predictions outside online timers; the full reference must not enter an online stop decision.
- Main stop, class reference and entropy/confidence differ only in their stopping criterion and necessary work. Fixed-prefix is allowed to avoid work it does not require. Shared order/batch fixes selection advantage; a separate adaptive acquisition experiment must be named and analyzed separately.
- Strict interval separation is a reference rule motivated by deterministic residual/class preservation. [LazyGBM, §4.4.3](https://www.mdpi.com/2227-7390/14/13/2343) processes a prefix of trees after receiving a complete feature vector. Our rule processes a prefix of feature blocks and bounds all reachable tree leaves. Call it **class-preserving reference rule**, never an original LazyGBM reproduction. Likewise the existing leaf-mask evaluator is QuickScorer-inspired, not official QuickScorer code.

## Minimal useful strong acquisition extension, conditional rather than current execution

If an acquisition extension is necessary, prioritize TAFA's discrete template-search/conditional cached-loss route, since it challenges cheap routing without imposing online combinatorial search. Use genuine processing blocks as actions. On **fit data only**, evaluate prespecified candidate masks using this project's common frozen partial-probability provider, cache their CE losses, and greedily select a small template library with the paper's minimum-across-templates objective; preserve mutation/search settings and initial-block selection in a freeze record. The observed-coordinate kNN loss estimate and a fixed template library are explicitly supported by TAFA §3.2 and its footnote. Online, route using only actual observed values, training donors and cached template losses; reveal genuine blocks and output the same common partial predictor. Record that grouping and interval-minimax partial prediction are adaptations. Omit §3.4 continuous refinement because the frozen HGB is not differentiable; omission is not a claim of reproducing all TAFA variants.

Use fit-measured real block durations only as estimates for a template cost term, and count **all** online kNN, routing, feature processing and prediction work in the final objective. Additive duration estimates do not become measured complete time and are not hard deadlines. Templates may overlap in statistical content; actual blocks remain distinct and their shared internal primitives must follow the existing processor. Select cost/stop settings only on development data and freeze before external access. Do not build this extension merely to create another algorithm name: the current main comparison already tests whether certified probability-loss stopping adds value beyond cheap prefix, confidence/entropy and class-preserving reference rules for a fixed predictor.

Current decision: **GO for implementing/timing the two common-classifier controls and confidence/entropy sensitivity. CONDITIONAL for a discrete TAFA adaptation if its independent acquisition question is retained.** Native DIME/SEFA/AACO/TAFA systems belong in an explicitly separate comparison with their own predictor and training costs; the certified paper's claim is a pointwise relative-probability-loss processing capability, not universal AFA dominance.
