# Frozen HAR certificate test execution plan

Preparation status: this plan and driver may be inspected without test access. No held-out archive member/cache may be opened before the root-owned `FROZEN_BEFORE_TEST_ACCESS` lock explicitly authorizes the method and official test access. The method freeze follows the checkpoint-only development tuning and separate stopping-control development. This document does not authorize execution.

Reuse the three already development-selected HGB predictors and temperatures, their original fit-only float32 scalers, their original fit-cost/gain feature orders, and the one common checkpoint schedule selected solely by equal-seed mean tight-minimax complete time at delta 0.025. No model, preprocessing, feature order, tolerance, schedule, seed or test cohort is selected using test outcomes. No refit is performed. Original uniform-four-block schedule A is retained as an auxiliary primary-tolerance schedule control when the chosen schedule differs from A. All previous failure/development records remain retained.

The main prediction grid has 17 specifications: tight interval-simplex minimax, coordinate-relaxed minimax and tight-bound midpoint output, each at deltas 0, 0.01, 0.025, 0.05 and 0.1, plus native and same-backend compiled exact full processing. The primary tolerance is 0.025. The main reference q is the temperature-scaled compiled full frozen model. Native softmax(_raw_predict/T) is the semantic conformance comparator and a contemporary complete-time control. Main efficiency is judged against the faster contemporary native/compiled complete processing, including only model-used feature blocks, not against a deliberately slow Python traversal.

All 2947 released test windows from the nine official held-out subjects receive the entire main grid. These untimed probability/outcome passes use the precomputed unstandardized feature cache with only selected block slices revealed online; full reference probabilities and labels never enter stopping policies. The first 24 windows separately verify actual raw recomputation against the selected-cache observer at every delta/output rule, including identical probabilities, block counts/fallback, native/compiled conformance, score/probability containment and every-label excess bounds. A failed check stops the run; it never triggers outcome-driven method changes.

Before computing any test prediction/reference, freeze the complete-time cohort using subjects and window IDs only: for each sorted held-out subject, uniformly select at most 100 windows without replacement using one generator seeded 7302026; combine and sort. The expected nine subjects each have at least 100 windows, yielding the same 900 windows for all seeds and methods. Do not inspect labels or risk when selecting this cohort. Save its IDs and per-subject counts immediately before reference inference.

Every timed specification executes actual statistic/FFT computation on its selected raw signal windows, float32 subtraction/division with frozen scaling before assigning float64 observed values, observer allocation, leaf mask updates, intervals, output/certificate, stopping decision and exact fallback. The timer begins after the released prefiltered/windowed inertial input is already in host memory; acquisition, UCI preprocessing, transmission, archive reading, off-line cache construction, reference checks and result serialization are excluded and identified. All measured methods share the same raw operators and compiled tree backend when applicable. Warm each specification once, then execute three repetitions per cohort window with seeded randomized method order; use all seeds and retain every execution. Partial-method instrumentation/traces are separate from primary timers. Complete timers include the actual pipeline's small output/result assembly costs.

Report two distinct denominators: the main risk/time table uses probabilities and times from the same 900-case cohort; all-2947 risk, reference excess and every-label certificate checks are an additional full-test outcome table. Do not attach 2947-case risk to 900-case time as though sampled identically. Report all three seed results and equal-seed averages; do not select the best seed. P95/P99 complete time and full fallback/block counts are descriptive software latency measurements, not a hard-real-time guarantee. Statistical resampling is handled by the root's shared held-out-subject plan, not independent overlapping windows.

Main per-seed NPZ keys: subjects, labels, test_indices, method_names, deltas, reference_probabilities, probabilities[method,case,class], certificates, block_counts, fallback. Auxiliary schedule outputs use their own NPZ. Timing JSONL includes original official test row index, subject, seed, repetition, method, delta, probabilities, certificate, block count, fallback and complete milliseconds; all methods use the identical frozen cohort. No timings from cached features are admitted.

The root lock must freeze selected model registry, training cache/operator, certificate and leaf-mask kernels, generic pipeline, checkpoint-repair pipeline and selected schedule record, each seed's frozen order record, this test driver and test-loader hashes. The loader produces a fresh D-drive test cache and manifest tied to that same lock and immutable F-drive source. The driver verifies those hashes and test cache provenance before loading test arrays. It writes only a new D-drive results directory; existing execution configurations or completed results are never overwritten. Technical failure records and partial outputs are retained and a new explicitly documented repair tag is required.

The assigned comparator agent additionally freezes three stopping controls before test access. The score-separated class-preserving control constructs a minimax probability only after strict logit separation, also requires the returned probability's argmax to match the certified winner, and guarantees the full model's class rather than probability loss. Fixed-prefix and entropy controls use center-imputed mean completion of unknown standardized coordinates and frozen per-seed settings selected from full development outcomes; they have an empirical development mean-risk target and no individual all-label loss guarantee. Their code and setting-state hashes belong to the root lock. The driver integrates their public frozen API without selecting anything on test.

With selected schedule C=[12,16,18], the timing randomization contains all 21 specifications in the same session: canonical17, auxiliary uniform-A tight minimax at 0.025, and the three stopping controls. Canonical probability arrays remain exactly17 methods; uniform-A and stopping controls use separate auxiliary NPZ files. Uncertified control certificates are explicitly NaN in those auxiliary binary arrays and None in JSON; they are not subjected to a false proper-loss-certificate assertion. All controls still report actual risk, reference excess, class agreement, maximum every-label excess and violations of the primary 0.025 criterion. The driver has no control/model selection procedure and does not run the official-test loader automatically.
